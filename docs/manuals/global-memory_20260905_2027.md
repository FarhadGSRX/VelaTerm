# 会话知识库

- 创建时间: 2026-09-05 20:27

- 更新时间: 2026-09-14 11:18

本文介绍“会话知识库”和“整理记录”。本地 Markdown 文件管理、编辑和导入见[本地笔记与知识库](knowledge-notebooks_20260910.md)。

知识库按“项目 → 会话 → 条目”保存知识、决策、约束和经验。生成内容独立保存，不随来源变化自动更新，用户可以手动编辑。它属于当前连接的应用后端，跨项目和会话共享；连接其他服务器时，查看的是该服务器的知识库。

它与会话内容搜索相互独立。会话搜索用于查找原始对话，知识库检索只查询已保存的知识条目。当前功能提供主动生成、会话内主题整理、查阅和维护，不会自动将条目内容注入新会话。

## 从会话整理知识

1. 在侧边栏或会话标签的右键菜单中选择“整理到会话知识库”。归档列表也提供同名入口。
2. 在对话框中选择 Claude 或 Codex。程序使用“设置 → 智能体”中的可执行文件路径；未配置时从已安装程序和 PATH 中查找。
3. 从下拉列表选择模型和思考程度，或保留默认配置。程序记住最近一次使用的智能体、模型和思考程度，下次打开时作为默认选择。思考程度按所选模型支持的档位显示；选择默认模型或模型未提供档位时，思考程度沿用 CLI 配置。Codex 模型列表由本机 CLI 查询，Claude 复用后端模型目录及已配置的模型。列表读取失败时可以重试。CLI 需要具备有效登录状态及可用模型。
4. 选择“整理并保存”。所选智能体将接收此会话的文字，通过其已有模型服务配置完成整理。
5. 在“整理记录”中查看进度、打开结果或来源。关闭窗口不会停止后台任务，可以主动取消等待开始或正在运行的任务；失败或中断的任务可以重试，重试保留原来的模型和思考程度。整理记录显示任务选择的配置；默认选项表示由 CLI 决定，不代表已经解析出具体模型或档位。

程序优先读取已有的智能体转录。没有可读转录时，使用该会话已经保存的终端录制，去除终端控制序列。两种来源都不可读时，会明确提示没有可读取的会话内容。终端录制保留的是可见屏幕文本，可能包含重绘内容；整理时不能将这类输出当作经过验证的结论。

来源快照保存整理当时读取的文字。项目名称、会话名称和归属在首次加入时独立保存，之后不会随外部项目或会话的修改、移动、归档或删除自动更新。再次主动生成会重新读取会话，并覆盖该会话此前生成的条目，包括用户已保存的手动修改；即使来源文本和模型配置相同，也会重新整理。如果本会话已有未完成的整理，再次提交会取消旧任务并由新任务替代。旧任务已经运行时，新任务会等待旧进程停止后自动开始；旧记录仍保留在整理记录中。

## 会话内整理与覆盖

整理分为三个阶段：

- **提取主题**：分段读取会话，提取可复用知识，只在本次任务内合并相同主题，供后续片段匹配。不读取其他会话条目，也不把旧条目的人工编辑作为生成依据。
- **合并知识**：逐个主题整合本次会话中的贡献，保留知识、约束与不确定性。提示词要求明确处理后续修正和矛盾，不自行编造结论。
- **保存条目**：后端校验字段、来源、关联和版本，并在单个数据库事务内替换该会话的生成结果。同标题条目保留 ID 并新增修订；本次不再生成的旧条目及其修订历史会被删除，指向这些条目的关联也会移除。生成成功但没有可复用知识时，该会话旧的生成条目会清空。任何校验失败、取消或版本冲突均保留原结果，不写入部分条目。

智能体返回结构化内容，由程序负责数据库操作。知识条目通过关联列表相互连接，反向引用自动计算。来源快照与修订历史不依赖原会话继续存在。

智能体整理仍需要人工判断内容质量。发现不准确之处，可以直接编辑条目，或从修订历史恢复旧版本；恢复会产生新修订，保留操作前的版本。

## 查阅与维护

从右侧“知识库”标签页进入“会话知识库”，可以按“项目 → 会话 → 条目”逐级展开。会话知识库、已归档会话与本地知识库是同级根目录；点击项目或会话名称，在主内容区查看对应条目列表，点击条目则打开正文。

列表页的路径导航旁提供紧凑的搜索、标签筛选、排序和刷新工具。阅读条目或历史版本时，仅保留路径导航和搜索入口；点击搜索图标返回当前会话的条目列表，原有筛选条件继续保留。

- 检索标题、摘要、正文和标签，支持中文及多个关键词；关键词之间采用 AND 条件。搜索时结果按相关度排列，标题命中排在前面，每条结果同时列出直接关联的条目。
- 用标签筛选，按最近更新或标题排序。当前会话的条目按每页 40 条分页，项目与会话目录不受条目分页截断。
- 打开条目后，查看 Markdown 正文、关联知识条目、反向引用、来源和修订历史。
- 手动新建的条目放在“手动创建”分组。支持编辑、删除，以及导出单篇 Markdown。删除条目会一并删除其修订历史，但不删除来源会话和已保存的来源快照。
- 条目详情、编辑页、来源快照、历史版本、整理对话框和任务记录都有独立 URL。项目、会话、搜索、筛选、排序和分页也记录在 URL 中。

## 已归档会话（Collections）

归档会话在知识库中与知识条目一起管理。右侧知识库树的“会话知识库”下方是“已归档会话”，按归档前的项目分组展示；左栏头部的“已归档会话”按钮也直接打开这个位置。

- 主内容区按项目列出全部归档会话；打开一个会话后，可在“对话”与“知识条目”两个页签之间切换，查看完整对话记录、该会话已生成的知识条目，以及从当前会话继续整理知识的入口。
- 顶部搜索框对归档内容做全文搜索，搜索范围只包含已归档会话。命中后按会话分组列出，可直接在结果中恢复、导出或删除整个会话。
- 列表和详情中都提供同类操作：恢复到常规会话树、整理到会话知识库、导出完整上下文（Claude/Codex），以及连同录制一并永久删除。
- 归档、恢复与删除不改变已有知识条目；来源快照和条目内容独立保存。恢复后的会话可以继续对话。

归档会话的浏览、搜索与查看原先位于独立的归档浮层，现已全部并入知识库，不再单独弹出窗口。

## 旧数据兼容

升级时，只有一个来源会话的旧条目归入该会话；已混合多个会话的条目完整保留在“历史合并条目”分组，不强行拆分，也不会被某个会话的再次生成覆盖。没有来源的条目归入“手动创建”。仍存在的项目信息只在迁移时补全一次；无法确认项目的来源放入“来源项目未知”分组，保留原有来源会话名称及快照。

## 数据与运行约束

会话知识库的权威数据位于应用现有 SQLite 数据库的 `memory_*` 表中，独立于 `session_fts` 等会话搜索索引。前端仅保存展示及尚未提交的表单状态，最终校验、版本检查、重复检测和写入都在后端完成。

不同来源会话的整理可以并行执行。同一来源会话一次只运行一个整理任务，再次提交时只保留最新的待执行任务，不会累积排队。任务保存提交时的来源快照、智能体、模型和思考程度；即使来源快照或配置不同，同一会话的新任务也会替代此前未完成的任务。人工编辑可以同时进行；生成过程中如有人编辑或删除了该会话的旧条目，任务会报告版本冲突，保留人工操作的结果，随后可以重试。不同会话可以使用相同标题，同一会话内仍不允许重复标题。

当前单个来源上限为 2,000,000 个字符；每段提取最多 24,000 个字符；单次模型输入上限为 350,000 个字符；单条正文上限为 200,000 个字符。单次 CLI 调用限时 10 分钟，输出流上限各为 8 MiB。超限会明确失败，不截断后继续入库。

待执行任务保存在数据库中，应用重启后自动继续处理尚未开始的任务。运行中的任务定期更新心跳；连续两分钟没有心跳的任务会在任务调度、读取任务列表或启动任务时标为中断，可使用保存的来源快照重试。等待开始期间不计算执行超时。取消待执行任务后，该任务不会启动；取消运行任务时显示“正在取消”，待智能体进程停止后再启动本会话的替代任务。取消任务不会删除来源快照。

运行日志默认位于应用数据目录的 `logs/runtime-*.log`，可用 `VLX_MEMORY_LOG_DIR` 覆盖；`VLX_MEMORY_LOG_LEVEL=error` 只记录错误，`off` 关闭本模块日志。日志记录任务及步骤、输入输出数量、耗时、字符数、SHA-256 和数字 Token 用量，不记录完整提示词、来源文本、模型响应、认证信息或 stderr 内容。原始证据在来源快照中查阅。

## 与代码图谱关联

知识条目可关联项目代码符号，并从“代码引用”跳转到图谱。代码文件变化后显示复核提示；确认复核不会改写条目正文。会话中的 Agent 也可以通过 `vkb` 按需查询代码和条目。具体操作见[代码图谱与知识库](codegraph_20260905_2027.md)。
