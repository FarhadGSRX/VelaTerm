# 代码图谱与知识库

- 创建时间: 2026-09-05 20:27

> 代码图谱目前是实验性功能，界面、数据结构和索引行为都可能在后续版本中调整。

代码图谱使用 CodeGraph 分析项目中的符号和关系。知识库保存设计决策、约束和经验；两者通过代码引用关联，分别提供当前代码结构与历史设计背景。

## 核心能力与页面入口

整合以经过校验的 CodeGraph 1.6.0 发布包为基准。代码探索直接使用上游 `ToolHandler` 的 `codegraph_explore`，搜索使用 SDK 的相关性排序，调用者、被调用者、影响范围和调用路径使用上游图遍历算法。界面使用 VelaTerm 的 React 组件、主题与 URL 导航；没有混装主分支尚未包含在该发布标签中的 Svelte 界面。

- **概览**：查看文件、符号和关系数量、语言与符号类型分布，以及自动同步状态。点击分布项可进入相应筛选结果。
- **符号**：按名称、路径或上游字段语法查询，例如 `kind:function`、`lang:rust`、`path:src/session`。打开符号后查看带语法高亮的源码及按关系类型、文件组织的传入和传出关系。推断关系有单独标记，行号链接可定位调用位置。
- **代码探索**：描述功能或调用流程，查看上游返回的源码与关系上下文。此查询由本地程序执行，不调用 AI 模型。
- **文件**：按路径浏览已索引文件，点击文件进入该文件的符号列表。
- **调用者与被调用者**：在符号详情选择方向和深度，查看多层调用关系。默认深度为 3，最大为 6；最多展示 500 条结果，并保留完整数量和截断提示。
- **影响分析**：在符号详情切换到此页，选择遍历深度，查看可能受影响的符号与文件。默认深度为 3，最大为 6；最多展示 500 个符号和 2,000 条关系，截断时保留完整数量并显示提示。
- **调用路径**：在符号详情搜索目标符号，查看沿调用边前进的最短路径。未找到路径仅表示索引中没有匹配的有向调用路径。

工作目录通过目录菜单切换，完整路径可在菜单中查看。概览、符号、文件、探索问题、分页、符号详情页、影响深度、调用目标和源码行号均写入 URL，可刷新或使用浏览器前进、后退恢复。

## 启用项目索引

1. 在左侧项目或集合的右键菜单中选择“实验性功能”→“代码图谱”。
2. 首次使用时选择“下载 CodeGraph”。当前连接的后端从 GitHub 下载固定的 1.6.0 版本，并核对内置 SHA-256 校验值。无需另行安装 Node.js。
3. 选择工作目录，再选择“启用索引”。项目目录以及会话、分组关联的其他工作目录分别列出；Git worktree 使用独立索引。集合需要先有带有效工作目录的会话。
4. 等待状态变为“可用”，即可搜索符号或文件路径。初始化在后台执行，关闭界面不会取消任务。

“同步索引”用于手动更新或重试。查询代码前会执行增量同步。同一后端、同一工作目录复用 SDK 查询进程，并在进程运行期间通过上游原生文件监视器同步变更。查询进程闲置 5 分钟后退出，下次查询会重新打开索引并补齐变更。停用索引会终止对应进程。概览每 30 秒更新自动同步状态；监视不可用时仍在查询前同步，不会将旧结果伪装成当前结果。停用会停止正在执行的索引任务，并保留索引文件和条目关联；之后可以重新启用。任务中断后，过期的运行状态会在读取列表时转为可重试的失败状态，最长约两分钟。单次索引任务上限为 30 分钟。

索引存放于各工作目录的 `.codegraph/` 中，由 CodeGraph 管理。VelaTerm 通过 SDK 执行索引，不调用上游的 Agent 安装程序，也不安装 Git hooks。项目根目录若是仓库中的子目录，只索引所选择的目录，不自动扩大到整个仓库。

## 查看代码关系

搜索结果列出符号名称、类型和位置。打开符号后，可查看源码、传入关系、传出关系和相关知识条目；点击相邻符号继续浏览。

关系来自静态分析，可能不完整或存在不确定性，不能代替运行验证。页面最多展示每个方向 200 条关系、600 行符号源码；超出时会提示。源文件超过 4 MiB 时不展示内容。查询期间文件变化会显示提示，此时应重新同步。

项目、工作目录、符号、关联编辑界面，以及搜索和分页都有独立 URL。可以复制链接、刷新页面、在新标签页打开，或使用浏览器前进和后退。链接需要在同一个后端及有效登录状态下访问。

## 关联与复核条目

在符号详情中选择“关联知识条目”，选取已有知识条目并核对正文与源码，然后保存。条目详情中的“代码引用”可以返回对应代码；图谱中的条目链接可以打开完整条目。

关联保存的是项目、工作目录、文件路径、符号身份及已复核文件的 SHA-256 摘要。文件变化后会提示“需要复核”；文件不可读或已删除时显示“不可用”。这是文件级提示，同一文件中的其他代码变化也会触发复核。条目详情打开时会定期检查这些引用。

选择“核对代码与条目”查看当前内容，确认无误后选择“确认已复核”。后端会再次检查所显示的文件摘要和条目版本；操作期间发生变化时要求重新加载。复核仅更新代码引用，不修改条目正文。需要修改结论时，使用知识条目原有的编辑功能。

符号被删除或重命名后，不会自动关联到同名的其他符号。可以移除旧关联，再为合适的符号建立关联。删除条目会移除其关联；删除项目会移除其索引管理记录和关联，不删除其他条目或工作目录中的索引文件。

## 会话内查询

VelaTerm 启动的终端与 Agent 会话均提供 `vkb` 命令，不再提供旧名称的命令或技能别名。更新应用后会安装新命令并清理旧入口；现有会话若找不到 `vkb`，可以重新启动会话进程。其他能运行终端命令的 Agent 也可以使用 `vkb`。

启用应用的内置技能后，Claude 可用 `/vkb`、Codex 可用 `$vkb` 调用配套技能。已有用户会在新版应用启动时获得更新，也可在“设置 → 通用 → Vela 技能”中重新安装；若智能体仍未列出新技能，需要重启该智能体会话。

```sh
vkb status
vkb explore "会话如何创建并选择工作目录"
vkb search "greet"
vkb node "搜索结果中的符号 ID"
vkb callers "符号 ID" 2
vkb callees "符号 ID" 2
vkb impact "符号 ID" 3
vkb path "起点符号 ID" "终点符号 ID"
vkb files "src/session"
vkb memories "设计决策"
vkb memory "搜索结果中的条目 ID"
```

`explore` 返回原版代码探索结果；`callers`、`callees` 和 `impact` 接受可选深度，`path` 接受两个搜索结果中的精确符号 ID，`files` 可按路径过滤。调用遍历结果包含 `relations`、`total`、`depth` 和 `truncated`，便于识别显示范围。

`search` 的符号列表使用相关性排序，并通过 `hasMore` 指示是否还有结果；旧的基础 `knowledge_search` IPC 接口仍保留兼容。`search` 分别返回代码搜索结果和知识库摘要；`node` 返回精确符号的源码、关系和关联知识条目；`memory` 返回条目正文、来源、修订信息与代码引用。代码查询按命令执行时的实际工作目录选择索引，子目录可使用所属项目的索引，嵌套的独立 worktree 不会借用主工作区索引。

索引未启用或查询失败时，结果明确给出代码不可用状态，仍可查询知识库。这些命令不会安装运行时、启用索引或修改条目。

## 本地、远程与数据位置

运行时安装于应用数据目录的 `codegraph/1.6.0/`；任务状态和条目引用位于应用数据库的 `knowledge_*` 表中。索引在代码所在后端执行，浏览器和 SSH 连接通过现有后端通信读取结果，无需新增图谱服务端口。不同后端分别保存索引配置和知识库。

运行时的遥测、更新检查和上游独立守护进程均关闭。SDK 查询进程由 VelaTerm 管理，通过私有标准输入输出通道通信，不新增监听端口。索引计算本身不调用 AI；Agent 查询得到的代码或条目可能进入其已配置的模型服务，数据处理方式与普通 Agent 读取源码相同。

日志默认位于应用数据目录的 `logs/runtime-*.log`。可用 `VLX_KNOWLEDGE_LOG_DIR` 指定目录，或用 `VLX_KNOWLEDGE_LOG_LEVEL=error` / `off` 限制日志。日志不包含源码、查询文本、条目正文或认证信息。
