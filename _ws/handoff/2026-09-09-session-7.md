## ⚠ The finding that matters: a clean auto-merge broke a feature

**`src/hooks/useKeyboardShortcuts.ts` merged with NO conflict and swallowed a plain `Tab`.** Shell
completion would have silently stopped reaching the terminal.

Upstream removed the early `if (!mod) return` gate and pushed `hasMod(e)` down into each individual
branch. Our Cmd/Ctrl+Tab cycling (`e19bcb2`) sits *between* those branches and depended on the gate
that went away. Both sides were individually correct; the composition was not.

**A conflict marker fires on overlapping edits to the same lines. It cannot fire on a dependency
between distant lines.** That is not a limitation of `ort` — it is what "merge" means. The two files
reviewed hardest that night (`index.css`, `settings.ts`) both conflicted loudly and were therefore
*safe by construction*; the one that broke never conflicted.

**Reviewing the conflicted files is not reviewing the merge.** The auto-merged set is larger,
unexamined, and is where this class lives. The only instrument that caught it was
`useKeyboardShortcuts.tabCycle.test.tsx` — a test written for a feature shipped two weeks earlier,
pinning behaviour nobody was changing. **That is the argument for keeping behavioural tests that look
redundant.**

Second-order: the first fix was also wrong. `hasMod` is platform-**exclusive** (`Cmd xor Ctrl`) and
broke *"treats Cmd the same as Ctrl"*. Tab cycling deliberately takes either modifier on every
platform, the way a browser's Ctrl+Tab does. Correct guard is `(e.metaKey || e.ctrlKey)`.

## Ruling that inverted: `feat/windows-default-shell` is worth MORE now

`win/velaterm-winshell` proposed *"they built half of it themselves — take THEIR `defaultShell`."*
**False, and checked at the merge base:** `56dad0f:src/store/settings.ts:87` already had
`defaultShell`. It was never ours; our branch only ever added `agentShell`.

What upstream actually built is `default_shell(kind, data_dir)` at `manager.rs:2065`, which on Windows
returns `"powershell.exe"` for any non-Terminal session. **They conceded the premise — agents want a
different shell from terminals — and hardcoded 5.1 as the answer.** `agentShell` is the configurable
form of a distinction they now agree exists.

**And it explains why upstream has never hit the pwsh escaping defect**: they always launch agents on
5.1, the dialect the current escaping is correct for. `agentShell` is what makes pwsh 7 reachable.
**That branch and `fix/pwsh-native-arg-escaping` ship together or not at all.** This reasoning is the
second section of PR #61 and is what carries it.

## ⚠ Structural debt — OWED, not done

Every fix made during the *last* regeneration had to be re-derived identically tonight:
`fontSelect.test.tsx`, `sidebarView()` parsing `kind`, `stickyTab.test.ts`'s version literal, and four
test fixtures. **They only ever existed on `fg-main`, and regeneration discards `fg-main`.**

Agreed with `win/velaterm-winshell`, whose reframe is the right one: *a feature branch that does not
work against current upstream is not clean, it is stale.* Landing them is maintenance, not scope
creep — and the cost I had priced ("the branch stops being a clean one-concern artifact") falls on a
branch class we have never sent: **every PR we have ever opened is `fix/*`.**

**The agreed fix turned out to be unexecutable, and this is the correction.** The plan was to land
them on `feat/files-collapse-all` as one labelled `chore:` commit per sync. Checked the target branch
before doing it:

```
feat/files-collapse-all base   ea6236a (v0.1.102)
  src/components/Select.tsx    ABSENT
  function sidebarView()       0 hits
  MIRROR_LAYOUT_VERSION        = 1
  fontSelect.test.tsx          hand-rolled DOM, correct for its base
```

**Every fix targets a surface that does not exist there.** A Select-based font test cannot pass with no
`Select.tsx`; there is no `sidebarView()` to patch; the version fix removes a hardcoded `1` where the
constant genuinely is 1. Landing it would produce a branch that fails its own suite.

The diagnosis stands and is worse than "the fixes are homeless": **the branch is six releases stale.**
The reconcile commit is a symptom of that, not its cure.

**What actually solves the cost, with no new machinery:** re-derivation is expensive only when done
from scratch, and it need not be. Every regeneration pushes a backup ref *before* the force-update, so
the previous reconciliation commit is always recoverable:

```
origin/backup/pre-v0.1.105-regen   99544db   ← the ONLY copy of that tip anywhere
origin/backup/pre-v0.1.108-regen   3411de7
7deb188                            this sync's reconcile commit
```

**Standing procedure, now in the runbook: before resolving a regeneration, read the previous sync's
reconcile commit.** That converts rediscovery into review, which is the cost actually being paid.

The staleness itself — rebasing or recreating `feat/files-collapse-all` on current upstream — is a
separate and larger decision about what the branch *is*. **Open, for fg, when no build is in flight.**
