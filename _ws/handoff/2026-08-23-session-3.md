## The one real bug found — worth an upstream PR

**Item 6 is not a feature, it is a fix**, and it is the best upstream candidate we have produced.

Ticking "save workspace" and confirming stored the answer, yet the box came back unticked every
launch. `setSaveWorkspaceOnQuit` reaches localStorage synchronously, but `pushSetting` debounces the
**backend** write by 400 ms and `confirm_quit` kills the process well inside that window. Startup
`reconcileSettings` then treats the backend as authoritative and overwrites any differing local value
— so the skipped flush does not merely fail to save, **it reverts the value already written**.

Fix: `await flushNow()` before approving the exit. **Not specific to the checkbox** — any setting
changed in the last 400 ms before quitting was reverted the same way.

## Things a fresh session will otherwise get wrong

- ⚠ **Worktrees branch from `main`, not from your checkout.** All three teammates landed on `d098f5a`,
  four commits behind. Each caught it and ran `git merge --ff-only <base>`. **Put the expected base
  SHA *and* a hard STOP in any future brief** — the check without a stop condition is only a
  suggestion, which is exactly how it played out.
- ⚠ **Adding one key to `en.ts` breaks `tsc` for all ten other locales.** `t()` does fall back per key
  (`dict[key] ?? en[key]`), which makes English-only look viable, but every dictionary is typed
  `const xx: typeof en`. Runtime is forgiving; the type system is not.
- ⚠ **`node_modules` is `.gitignore`d as `node_modules/` — with a trailing slash.** That matches the
  real directory but NOT a symlink of that name, which is how worktrees get a toolchain. Stage
  explicitly in a worktree.
- **The Mac shows no quit dialog on window close, and that is correct.** `lib.rs:922` gates the
  `CloseRequested` arm behind `#[cfg(not(target_os = "macos"))]`. `ExitRequested` is cross-platform,
  so **Cmd+Q does prompt**. Nothing to fix.
- **`FontSelect` is defined in `SettingsModal.tsx:341`**, not `settingsPanels.tsx`.
- **Dead locale keys**: `tree.viewManage`, `viewSetPrimary`, `viewRename`, `viewDelete`, `viewName`,
  `viewDeleteTitle`, `viewDeleteConfirm` have no code references in any locale. Left alone
  deliberately — unrelated changes in a feature PR is what upstream's #39 objected to.

## Parallel-teammate notes, if repeating the pattern

It worked well: three items, ~9 to 17 minutes each, all three self-caught the wrong base, one caught a
factual error in my brief, one asked a genuinely load-bearing blocking question.

What made it work was **demanding specific measurements rather than diligence**. "Report
`git log --oneline -1`" and "the baseline is 32 files / 230 tests" produce detection; "make sure
you're up to date" produces agreement. Same for the completion bar: every teammate had to revert its
own change, watch its test fail, and quote the failure message back.

The `kind` discriminator on `SidebarTreeView` was deliberately made **required** rather than optional,
because item 12 adds a third variant and a required discriminator makes the compiler enumerate every
site that must handle it. The teammate verified this empirically — adding `| "scripts"` produced
exactly one error, `LeftSidebar.tsx(221,13)`. That is pre-paid work for item 12.
