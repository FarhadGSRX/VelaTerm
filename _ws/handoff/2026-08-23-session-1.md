## Facts established this session (don't re-derive)

- **All four shipped accents fail WCAG AA** for the white text drawn on them: green 2.16, blue 2.66,
  amber 2.06, violet 2.62 (AA needs 4.5). White is hardcoded at `index.css:132-136`; ~11 sites use
  `background: var(--accent)`. Meanwhile xterm *is* protected (`usePtySession.ts:216`,
  `minimumContrastRatio: 4.5`). Seen in the wild: the amber **Quit** button.
- **One bundle serves all three clients.** `web/mod.rs` embeds the same `../dist` the desktop uses;
  `main.tsx:41` picks `MobileApp` vs `App` at runtime. No separate mobile/web build. **This resolves
  Codex's cross-client concern — theme sync is not a protocol problem.**

  `applyTheme()` (`theme.ts:133-138`) writes `dataset.theme` and nothing else. Confirmed visually by
  fg: forcing light on a dark-mode OS leaves native checkboxes dark. A one-line fix, still unshipped.

  grep finds no handling anywhere. Reproduced live. Covered by upstream #26 item 1.

## Gotchas that cost time

- **RTK rewrites empty command output to the literal `ok`.** `git status --short` printing `ok` means
  *clean*. Use `--porcelain | wc -l` when you need a number.
- **Vault files carry ReadOnly attributes**; moving folders fails until cleared recursively.
- `consult-codex` had three Windows bugs, now fixed (`.cmd` shim resolution, multi-line argv through
  `cmd.exe` silently dropping the prompt, cp1252 file I/O). **Its sandbox still blocks repo reads on
  Windows**, so repo-aware Codex review is unavailable here — treat its output as design review only.
- Setting `core.autocrlf` *after* cloning does not fix an existing CRLF tree; git's stat cache reports
  clean. Force with `git rm --cached -r . && git reset --hard`.
