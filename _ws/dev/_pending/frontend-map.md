# VelaTerm Frontend Map

Scope: `src/`, `index.html`, `vite.config.ts` at fork commit d098f5a. Read-only analysis.

## 1. Component Map

Entry chain: `index.html:31` loads `src/main.tsx`, which renders `<ErrorBoundary><LoginGate>{isMobileView() ? <MobileApp/> : <App/>}</LoginGate></ErrorBoundary>` (`src/main.tsx:39-43`). `LoginGate` (`src/remote/LoginGate.tsx`) gates browser/remote clients behind token auth before `App` ever mounts, because `App` calls `loadTree()` over the transport as soon as it mounts (comment at `LoginGate.tsx:11-12`). Desktop Tauri clients pass through immediately.

`App.tsx:202-237` lays out the desktop shell as five fixed regions plus ~15 modals:

- **TitleBar** (`src/layout/TitleBar/TitleBar.tsx`) — branding, theme toggle, appearance/settings entry, panel-collapse controls, dev/update badges. Owns `SettingsModal.tsx`, `ConnectRemotePanel.tsx`, `RemoteAccessPanel.tsx`.
- **LeftSidebar** (`src/layout/LeftSidebar/LeftSidebar.tsx`, 889 lines) — workspace header, search, `ProjectTree.tsx` (the project/group/session tree), multi-select, inline rename, context menus (shared with tab bar via `../sessionMenu`), plus recursively splittable "sidebar tree views" (`sidebarTreeLayout.ts`) each with independent filters. Also owns `ArchivePanel.tsx` and `GlobalSearch/GlobalSearch.tsx`.
- **CenterPane** (`src/layout/CenterPane/CenterPane.tsx`) — tab bar (`TabBar.tsx`) + a recursive split-pane area (`paneTree.ts`). Every open session pane stays mounted in an absolutely-positioned percentage rect; inactive tabs get `display:none` so xterm/PTY stay alive (`CenterPane.tsx:1-3`). Renders one of `TerminalView.tsx`, `DormantPane.tsx` (restored-but-not-yet-spawned placeholder), `doc/DocView.tsx` (lazy-loaded, CodeMirror+ProseMirror, >1MB chunk split out — `CenterPane.tsx:24-27`), or `browser/BrowserView.tsx` (placeholder div overlaid by a native child WebView, see §3).
- **RightPanel** (`src/layout/RightPanel/RightPanel.tsx`) — Inspector with Files/Info/Git tabs (`FilesTab.tsx`, `InfoTab.tsx`, `GitTab.tsx`) following the focused session's cwd.
- **StatusBar** (`src/layout/StatusBar/StatusBar.tsx`, 665 lines) — session counts, branch/worktree marker, per-session permission toggle, notification toggle (left); working/waiting/replied aggregate counts linked to sidebar filters, live-tab count popover, remote-access status (right).

`NotificationsManager` (`App.tsx:44-47`) is a deliberately isolated null-rendering component subscribing only to `activeSessionId`/`notifications`/`windowFocused` so notification churn doesn't rerender the whole tree.

**Mobile** (`src/mobile/`): a parallel client selected once at startup by `isMobileView()` (`src/mobile/detect.ts:10-31` — desktop shells never qualify; browsers use coarse-pointer + short-side<768px, overridable via `?view=` or `vlx-view-mode` in localStorage). `MobileApp.tsx` reuses the same `termStore`/`transport`/`usePtySession` data layer but manages its own two-level navigation (`SessionListPage.tsx` → `TerminalPage.tsx`) with local `openId` state instead of the tab/split/keep-alive store slice (`MobileApp.tsx:6-9`).

## 2. State Management (`src/store/`)

Single Zustand store, no `persist` middleware — `src/store/termStore.ts:1414` (`create<TermStore>((set, get) => ({...}))`, 3679 lines total, ~720-line interface). Persistence is manual and layered:

- **Tree data** (`projects`/`groups`/`sessions`) is SQLite-backed on the Rust side; the frontend fetches it via `loadTree()` → `ipc/tree.ts:listTree()` and mutates through per-action IPC calls that each locally patch state then often re-`loadTree()`.
- **UI/appearance settings** persist to `localStorage` via `src/store/settings.ts` (`SETTINGS_KEY = "vlx-settings"`, `loadSettings`/`saveSettings`, `settings.ts:137-163`), then mirrored cross-shell through `src/ipc/settingsSync.ts` (`pushSetting`, debounced 400ms, `settingsSync.ts:50-55`) into backend SQLite `app_settings`, because Tauri's WKWebView and Electron's Chromium have separate stores that can't otherwise be unified (`settingsSync.ts:3-6`). Startup `reconcileSettings()` (`App.tsx:94-104`, `settingsSync.ts:88-115`) treats the backend as authoritative and reapplies any values it overwrites in the local cache — this is why `App.tsx` calls `hydrateSettingsFromCache()` after reconciliation.
- **Sidebar tree views** persist separately and debounced (200ms) to their own `localStorage` key (`termStore.ts:1288-1310`, key referenced as `SIDEBAR_VIEWS_KEY`), with a v1→v2 migration path (`PersistedSidebarViewsV1`/`V2`, `termStore.ts:169-177`).

`termStore.ts` was split for size: `docTab.ts` (68 lines — `DocTab` model, `docKindOf` extension classifier, `makeDocTab`) and `settings.ts` (172 lines — `PersistedSettings` shape/defaults/migration) are re-exported from `termStore.ts:92-95` so consumers keep one import path.

**`termStore.ts` is imported almost everywhere** (per the brief) because it owns nearly all cross-cutting state in one flat interface:
- Persistent tree mirror: `projects`, `groups`, `sessions`, `archivedSessions`, `treeLoaded`.
- Runtime: `runtimes: Record<SessionId, SessionRuntime>` (status/pid/agent/agentState — see §5), `epochs` (restart generation, bumping forces `TerminalView` remount), `ephemeralSessions` (unpersisted splits), `dormantSessions` (restored-but-unspawned), `pendingPrompts`/`pendingSpawns` (child-spawn confirmation queue).
- Tabs/panes: `openTabs`, `activeTabId`, `paneTrees: Record<SessionId, PaneNode>` (one recursive split tree per tab), `liveTabs`/`pinnedTabs` (background keep-alive set, capped by `maxLiveTabs`), `docTabs`, `browserTabs`.
- UI: collapse/width state, theme/accent/density/pane-style tokens, selection, filters, ~20 modal-open booleans, and the full `PersistedSettings` fields flattened directly into the store (`termFontFamily`, `shortcutOverrides`, `agentDefaults`, etc.).

Actions are grouped by comment banners inside the interface (`// Data loading and mutations.`, `// Tabs and splits.`, `// Layout.`, `// Notification navigation.` — e.g. `termStore.ts:872, 953, 1305, 1345`) rather than split into Zustand slices; it is one large `create()` call, not `combine`/slice-composed.

**Other stores** (all small, standalone modules, not sub-slices of `termStore`):
- `src/store/browserTabs.test.ts`, `docTabs.test.ts`, `sidebarTreeCollapse.test.ts`, `workspaceRestore.test.ts`, `termStore.agentStatus.test.ts` — these are tests *of* `termStore` behavior (not separate stores); I did not find independent Zustand stores outside `termStore.ts` — settings/docTab are plain modules, not stores.

## 3. IPC Boundary (`src/ipc/`, `src/platform/`)

**Transport abstraction** (`src/ipc/transport.ts`): a single module picks between two backends at runtime based on `isTauri` (`transport.ts:19-22`, `"__TAURI_INTERNALS__" in window && !window.__VLX_FORCE_BROWSER__`):
- **Desktop Tauri**: `@tauri-apps/api` `invoke`/`Channel`/`listen`. Most commands route through one dispatch command, `desktop_call` (`transport.ts:150-152`), except a whitelisted `DIRECT_DESKTOP_CMDS` set (`transport.ts:105-128`) that bypasses it for hot-path perf (`pty_write`/`pty_resize` avoid a thread hop per keystroke) or because they must run on the window-host thread (`open_remote_window`, `browser_*`, SSH commands).
- **Browser/remote**: a single WebSocket connection via `src/ipc/wsClient.ts` (protocol documented at `wsClient.ts:1-33`: JSON text frames for `invoke`/`pty-spawn`/`pty-detach`, binary frames `[1-byte sid length][sid][raw bytes]` for PTY output). Handles reconnect with exponential backoff (1s→30s cap), a 75s idle-heartbeat watchdog for half-open sockets, and E2EE pairing (`tweetnacl`) read from a URL fragment (`#pair=...`, never sent to the server — `wsClient.ts:118-144`).

Every `invoke()` call funnels failures through `recordRequestError` (`transport.ts:130-144`) for centralized console/ring-buffer/UI-banner reporting — callers never need their own error UI for a rejected command.

**The same frontend runs as a remote browser client** via this abstraction plus one more wrinkle: **remote-connection windows** (`isRemoteWindow`, `transport.ts:29-34`) are physically local Tauri `wry` windows that *force* WS transport (`__VLX_REMOTE__` sets `__VLX_FORCE_BROWSER__`) while retaining `__TAURI_INTERNALS__` for local-only native calls (clipboard writes, etc.) — so `isTauri` and "has native host" are deliberately different booleans (`platform/types.ts:29-35` documents `isRemoteWindow` as "the native-capable subset of isBrowser").

**Platform adapter** (`src/platform/`): a second, higher-level abstraction on top of transport, for non-IPC OS capabilities — dialogs, opener, badge, clipboard, window focus, quit-confirmation handshake, the `vela` CLI-install capability, notifications, and the built-in browser-tab child-view capability. `platform/index.ts:14` selects `electronPlatform` vs `tauriPlatform` by `env.isElectron` (browser/WS clients use the Tauri implementation, whose methods internally no-op or fall back where native capability is absent). **ESLint enforces** that application code never imports `@tauri-apps/*` or `electron` directly outside `platform/` (`platform/types.ts:7-9`, `platform/index.ts:4-6`) — this is a hard architectural boundary, not just convention.

`ipc/commands.ts` (591 lines) is the typed RPC surface: PTY control, shells, agent-install recipes, git-bash download, recording/transcript reads, session search, per-agent usage/rate-limit queries (Claude/Codex/Grok), worktree/branch/merge/diff operations, Gitea integration, spawn-skills install. `ipc/events.ts` (188 lines) wraps backend event subscriptions (`pty://exit|killed|status`, spawn requests, view requests, tree-changed, clone progress, menu actions, gitbash-download progress). `ipc/tree.ts` (230 lines) is CRUD for the project/group/session tree.

## 4. Terminal Layer (`src/terminal/`)

- **`registry.ts`** (167 lines) — a module-level `Map<string, Terminal>` giving shortcut/context-menu code access to live xterm instances by session ID, plus a parallel `SearchAddon` map and per-session `redrawHandlers` map. Also tracks OSC 52 drag-to-copy activity per session (`osc52Copies`, `registry.ts:96-107`) so the context menu can explain "already copied via OSC 52" instead of showing a disabled Copy action.
- **`outputScheduler.ts`** (286 lines) — the most load-bearing file in this directory. A shared write queue sitting in front of `term.write` so the *focused* terminal writes immediately while background-terminal output is coalesced and rate-limited to a **global** 128KB/frame budget (`MAX_BYTES_PER_FRAME`, `outputScheduler.ts:59`) shared across all background sessions — this prevents N noisy background agents from starving the foreground terminal. Layered refinements: an input-yield window (250ms after a keystroke drops the background budget to a 4KB trickle, `INPUT_WINDOW_MS`/`INPUT_TRICKLE_BYTES`, lines 70-72) so typing/IME stays responsive, and chunked flushing (64KB blocks, `FLUSH_BLOCK_BYTES`, line 79) because xterm only yields the main thread *between* `term.write` calls, not within one — an unchunked multi-MB backlog flush would freeze the UI for hundreds of ms. A 4MB per-session memory ceiling (`MAX_QUEUE_BYTES`) triggers fast-drain rather than ever dropping bytes. Gated by the `outputScheduler` store boolean (Settings → Advanced) as an emergency kill switch reverting to unscheduled writes.
- **`screenDetect.ts`** (377 lines) — infers agent activity (working/asking/waiting) by reading the bottom N rows of `term.buffer.active` directly (ported from a prior project "herdr"'s detector concept, `screenDetect.ts:3`). Always anchors at `buffer.active.baseY`, never `viewportY`, so user scrollback doesn't corrupt live-state detection (`screenDetect.ts:6`, `35-46`). Per-agent dispatch in `detectAgentScreen()`; Codex is explicitly a no-op here because its state is hook-only and must never be inferred from terminal text (`screenDetect.ts:56-59`).
- **`queryReplyGuard.ts`** (77 lines) — installed per-terminal (`usePtySession.ts:150-154`) to swallow terminal query replies and clipboard writes during history replay or when in mirror (non-owner) mode, so a shared/mirrored session doesn't produce duplicate answers to terminal queries or overwrite the clipboard with stale OSC 52 data.
- **`imeWebkitFix.ts`** (233 lines), **`grokBgRemap.ts`** (111 lines — a Grok-specific canvas background color remap), **`imageInput.ts`** (158 lines — clipboard/drop image handling feeding `uploadImage`/`uploadDocImage`), **`openLink.ts`** (41 lines — custom OSC-8 link handler because xterm's default `confirm()`+`window.open()` flow fails under Tauri).

## 5. Key Abstractions

1. **`PaneNode`** (`layout/CenterPane/paneTree.ts`) — a recursive binary tree of `LeafNode`(one session)/`SplitNode`(horizontal|vertical, `[a,b]` with percentage `sizes`), one per open tab, giving iTerm/tmux-style splits. Pure functions (`splitAt`/`removeLeaf`/`computeLayout`/`computeDividers`) — no React state inside the tree itself.
2. **`SessionRuntime`** (`types.ts:125+`) — the in-memory-only counterpart to the SQLite-persisted `Session`: process status, pid, detected `AgentKind`, `agentState`, and `agentStateSource` ("hooks" vs "legacy" — whether activity state came from an authoritative agent-CLI hook or a lower-confidence heuristic).
3. **Fit vs. mirror size mode** (`usePtySession.ts:8-18, 77-78`) — a PTY has one grid; exactly one client "owns" sizing (fit mode: resizes the PTY on container resize) while every other viewing client mirrors that grid faithfully via CSS scale transform without ever sending a resize. This is the mechanism enabling shared/multi-client session viewing (desktop + remote browser + mobile watching the same PTY).
4. **Transport vs. Platform** (§3) — two separate adapter layers: transport = IPC (invoke/listen/PTY streams), platform = OS capability (dialogs, clipboard, badge, window, notifications, built-in browser child-view). Both are runtime-selected singletons; app code never branches on `isTauri`/`isElectron` directly outside these adapters (with a few exceptions like `App.tsx` and `usePtySession.ts` that read `isTauri`/`env.isElectron` for behavior gating, not for choosing an IPC call shape).
5. **Output scheduler foreground/background split** (§4) — the reason a terminal-heavy multi-agent UI doesn't jank: per-terminal priority isn't xterm's job, it's this module's.
6. **Epoch-based remount** (`termStore.ts` `epochs: Record<SessionId, number>`) — bumping a session's epoch forces `TerminalView` to fully reconstruct (new xterm instance), the mechanism behind session restart.
7. **Ephemeral vs. persisted vs. dormant sessions** — three lifecycle states for a `Session` beyond plain running/exited: `ephemeralSessions` (scratch terminals, never in SQLite until `persistSession()`), `dormantSessions` (restored from a saved workspace, no process yet — `CenterPane` renders `DormantPane.tsx` instead of mounting a terminal, because mounting always spawns a PTY, `termStore.ts:685-689`), normal persisted+running.
8. **Vlinx visual tokens via `data-*` attributes** — theme/accent/density/pane-style/divider-style/nav-layout are written onto `documentElement` (`theme.ts:applyTheme`, `applyVisual`) and consumed purely through CSS attribute selectors in `styles/vlinx.css`; there is no JS-side per-component theming.

## 6. Runtime Narrative (desktop, cold start)

1. `main.tsx` installs a global `error`/`unhandledrejection` overlay (outside React, so it survives a React crash), applies a WKWebView glyph-width workaround (disabling `OffscreenCanvas` under Tauri, `main.tsx:33-35`), then renders `ErrorBoundary → LoginGate → App`.
2. `LoginGate` passes through immediately for `isTauri`; browser clients must obtain a session token first (POST login or E2EE pairing) before `App` mounts, because `App` will immediately try to talk over the transport.
3. `App.tsx` mount effect (`App.tsx:62-186`): `applyAppearance()` (theme + Vlinx tokens onto `documentElement`) → `loadTree()` with 3 retries at 1s/2s/4s backoff (transport may not be ready yet) → subscribes to WS reconnect (`wsClient.onConnState`) to reload the tree after recovery → detects available shells (`listShells()`) → `reconcileSettings()` against backend SQLite, reapplying any values it overwrote → subscribes to system theme changes, spawn requests, `vela <path>` open-project requests, `view://` (open doc/URL) requests, debounced `tree://changed` broadcasts (300ms), native menu actions, and a delayed (5s) silent update check.
4. Once `projects`/`groups`/`sessions` land in the store, `LeftSidebar`'s `ProjectTree` renders the tree; `CenterPane` renders whatever `openTabs`/`paneTrees` restored from the last workspace snapshot (if `saveWorkspaceOnQuit` was enabled) — dormant entries show `DormantPane` instead of spawning.
5. Opening/creating a session mounts `TerminalView` → `usePtySession(session, cwd, hidden)` (`hooks/usePtySession.ts`, 1019 lines): waits for JetBrains Mono font readiness (avoids caching wrong glyph-width metrics, `usePtySession.ts:80-97`) → constructs an `xterm.Terminal` with addons (Fit, Search, WebLinks, Clipboard w/ OSC52 provider, Unicode11, Image, then Canvas/WebGL/DOM renderer per settings) → registers it in `terminal/registry.ts` → installs the query-reply guard and custom key handler (Shift+Enter → ESC+CR for Claude/Codex, Ctrl+V passthrough on non-Mac, blocks app Ctrl+Alt shortcuts) → calls `spawnPty()` through the transport, which either spawns a new PTY or **attaches and replays** an already-running one → buffers bytes until the correct grid size is established, then replays → live output thereafter flows through `outputScheduler.writeTerminalOutput`.
6. Screen-detection (`screenDetect.ts`) and backend status hooks (`applyStatusSignal`/`applyScreenDetection` in `termStore.ts`) jointly update `SessionRuntime.agentState`, which drives sidebar status dots, the status bar's working/waiting/asking counters, and notification dispatch (`notify.ts` → `platform.notify`).
7. On unmount/close, `usePtySession` tears down listeners and (desktop) kills the PTY, or (browser) merely detaches this client while leaving a shared process running for other clients — this asymmetry is the mirror-mode/shared-session model in action (§5.3).

## 7. Existing Extension Points

- **`AgentKind`/`SessionKind` union types** (`types.ts:8,20`) — closed string-literal unions listing every supported agent (`claude`, `codex`, `opencode`, `copilot`, `cursor`, `antigravity`, `cline`, `pi`, `crush`, `kimi`, `kiro`, `grok`, `zoo`). Adding an agent means extending these plus `PERMISSION_TOGGLE_KINDS` (`types.ts:29`) if it has a skip-permissions flag, plus a `screenDetect.ts` case, plus `agentDefaults: Record<string, AgentDefaultConfig>` in settings.
- **`DIRECT_DESKTOP_CMDS`** (`transport.ts:105-128`) — an explicit allowlist Set for commands bypassing the unified `desktop_call` dispatcher; a clear, documented table to extend for new hot-path or main-thread-only commands.
- **`SHORTCUT_ACTIONS`/`DEFAULT_BINDINGS`** (`shortcutRegistry.ts:13-77`) — a small ordered list + per-platform default-binding record; adding a customizable shortcut means adding to both plus a `matchCombo` branch in `useKeyboardShortcuts.ts`.
- **`LOCALES`/`LOCALE_NAMES`** (`i18n/index.ts:24-55`) — locale list is a plain array; English (`locales/en.ts`) is the type-source-of-truth so every other locale dict is compile-checked against its keys (`i18n/index.ts:57-58`) — adding a language is mechanical and type-safe.
- **`Platform` capability interfaces** (`platform/types.ts`) — each capability (`DialogCapability`, `OpenerCapability`, `NotifyCapability`, `BrowserCapability`, etc.) is a small interface implemented once per shell (`tauri.ts`, `electron.ts`); adding a third shell means implementing this interface set, not touching call sites.
- **`PersistedSettings`** (`store/settings.ts:63-111`) + `SETTINGS_DEFAULTS` — one flat record with an established migration pattern (see the `gpuRender`→`termRenderer` migration at `settings.ts:141-148`) for adding a new persisted, cross-shell-synced preference.
- **Terminal renderer table** — `TermRenderer = "dom"|"canvas"|"webgl"` (`settings.ts:54`) with a straight-line `if/else if` addon-load branch in `usePtySession.ts:283-315`; a 4th renderer would extend this union + branch.

### Theming extension point (relevant to a user-supplied theme file)

**There is currently no file-based or user-supplied theme mechanism.** Theming is a closed system:
- `XTERM_THEME: Record<ResolvedTheme, ITheme>` (`theme.ts:72-103`) is a **hardcoded two-entry object** (dark/light) mapping directly to xterm's `ITheme` (16 ANSI colors + bg/fg/cursor/selection). No loader, no JSON import, no user file path anywhere near it.
- `AccentChoice` (`theme.ts:20`, `"green"|"blue"|"amber"|"violet"|"auto"`) and the other Vlinx tokens (`density`, `paneStyle`, `dividerStyle`, `navLayout`) are closed unions written as `data-*` attributes consumed by hardcoded CSS in `styles/vlinx.css` — extending them means adding both a union member and matching CSS rules, not dropping in a file.
- The **one existing "bring your own value" precedent** is font family: `uiFontFamily`/`termFontFamily` are free-text strings run through `fontStack()` (`theme.ts:64-70`), which quotes the name and appends a generic fallback chain — this is the only place user-supplied *unvalidated* text currently reaches rendering, and it's a font name, not a theme file.
- A real "load a user theme file" feature would need: (a) a new persisted field (probably a file path or the parsed JSON itself, following the `PersistedSettings` pattern), (b) a loader that maps that file's format onto `ITheme` for `XTERM_THEME`/`setXtermTheme()` (`terminal/registry.ts:126-130` already exists as the live-update hook — every registered terminal's `.options.theme` gets reassigned) and onto a new `data-*`-driven CSS token set or inline `style.setProperty` calls (parallel to how `applyVisual()` already does inline `--font-mono`/`--ui-fs` overrides at `theme.ts:36-39`) for the rest of the UI chrome. `applyVisual()`'s inline-CSS-var pattern is the most natural existing seam for that second half.
